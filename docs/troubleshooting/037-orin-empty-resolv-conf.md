# 037 — The Orin has no DNS: `/etc/resolv.conf` is empty

*Date: 2026-10-19 (cause found 2026-10-20)*

---

## What we saw

`apt-get install ros-humble-web-video-server` on the Orin: `Temporary failure
resolving 'packages.ros.org'`, while `ping 8.8.8.8` worked. `/etc/resolv.conf` was a
**0-byte regular file dated 1970**. Writing nameservers into it by hand fixed apt —
until the next reboot emptied it again (`dev_up.sh` then warned "routing works but
DNS doesn't").

## The cause

The image sets NetworkManager to hand DNS to `systemd-resolved`
(`/usr/lib/NetworkManager/conf.d/10-dns-resolved.conf`, `dns=systemd-resolved`), but
**`systemd-resolved` is disabled**. NetworkManager knew the router's DNS
(`IP4.DNS[1]: 192.168.0.1`) and had nowhere to put it. The enabled `resolvconf`
service doesn't write the file either, because it isn't a symlink.

## The fix

A NetworkManager drop-in that writes the file itself:

```
/etc/NetworkManager/conf.d/90-ranger-dns.conf
[main]
dns=default
rc-manager=file
```

`sudo nmcli general reload` applied it; `/etc/resolv.conf` became `# Generated by
NetworkManager` / `nameserver 192.168.0.1`, and it survives reboots. On the tether
alone there is still no DNS (no connection supplies one) — only apt cares.

Rejected: enabling `systemd-resolved` and symlinking the file — more invasive, may
fight the enabled `resolvconf`, and NVIDIA likely disabled it on purpose.

## Prevention

- A hand-edited `/etc/resolv.conf` is not a fix on a NetworkManager system; find who
  is supposed to write it (`NetworkManager --print-config | grep dns`).
- Re-check after joining any new network (venue, Pass 8).
